# 架构与路由

## 核心模式

- 页面装配层：读取页面配置并按顺序渲染区块。
- 区块组件层：每个区块变体都是独立模块。
- 变体注册表：统一维护 `kind + variant -> component` 映射。
- 多语言内容层：页面文案按页面拆分，统一由 locale 注册表驱动读取。

## 路由规则

- 路由按用户意图推断，不强制固定完整路由集合。
- 必备页面：
  - 首页（必须包含可提交留资的表单区块）
  - 联系页（必须可留资）
  - 隐私页
- 当产品条目 >= 2 时，启用 `/products/[slug]`。
- 多语言站点默认采用 `/{locale}` 段路由。
- 根路由 `/` 必须具备语言判断能力：
  - 先读用户已选择语言（cookie 或显式选择）
  - 再读 `Accept-Language`
  - 最后回退到默认语言
- 路由替换逻辑必须基于 locale 注册表动态生成，禁止使用 `^/(en|zh)` 这类硬编码正则。

## 多语言内容规则

- 页面多时，文案必须按页面拆文件，例如 `content/site/home`、`content/site/company`、`content/site/products`。
- 共享内容单独维护，例如 `shared` 中放 `pageLabels`、导航项、页脚项、企业通用资料。
- 页面组件只消费内容，不直接持有多语言字符串。
- 不允许随着页面增长继续把所有语言内容塞回一个巨型 `site.ts`。

## 扩展规则

新增首页结构时：

1. 新增区块变体组件。
2. 在注册表注册新变体。
3. 在页面配置中选择该变体。
4. 避免在路由文件内硬编码大段内容。

新增语言时：

1. 先在 locale 注册表中声明语言与市场信息。
2. 再补对应页面内容文件。
3. 校验根路由判断、切换器、hreflang、sitemap 是否自动覆盖新语言。
4. 禁止只补路由、不补内容结构。
